# 私有指导发布：条件性数学机制说明（未实现、未获保证）

隐私单元为固定客户端名册中某一个客户端的一条完整带标签记录的 replace-one；总记录数固定，标签可以改变。候选池 128 条、公开编码器及其版本、候选顺序、每类 top-8 配额都须在访问私有记录前固定。每条记录独立产生一票：按其标签类别，在该类 32 个公开候选中选余弦相似度最高者，以公开候选 ID 打破并列。把该客户端投票放入全局 128 维整数直方图 `h_i`。对任意相邻数据集，单条替换最多从一个 bin 移走 1、给另一个 bin 增加 1，故 `||h_i(D)-h_i(D')||_1≤2`，包括跨标签替换。重复记录仍逐条各一票；类别缺失应产生全零类直方图并仍输出固定配额，不能异常中止。

理想实数机制对 **每个** 坐标独立加入 `Laplace(0,2/ε)`；在 ε=4 时 scale=0.5。随后仅以带噪计数选择每类 top-8，平票按公开 ID，负值照常排序。发布公开候选 ID 的固定规则序列；cloud 可由 ID 恢复公开文本。原始票、逐条匹配、未加噪分数不得发布。以 Laplace 机制和后处理定理，若上述固定性、独立映射、噪声和唯一输出都成立，一次客户端发布为纯 `(4,0)` record-DP。零噪声 PRIVATE_ZERO 不具 DP。

当前私有选择器还有**跨客户端顺序去重**：先按客户端 1 的票选 8，客户端 21 再从剩余候选中选 8。DP 实现必须和 PRIVATE_ZERO 保持相同选择及输出规则，包括公开顺序，且不得用原始票另排顺序。理论上可以先发布客户端 1 的带噪选择，再令客户端 21 在其公开已选 ID 以外的候选中按自己的带噪直方图选取；对客户端 1 的记录变化，第二步仅是第一输出与固定的客户端 21 数据及独立随机性的后处理；对客户端 21 的记录变化，第一步不变而第二步是其带噪机制后处理。这个条件性组合论证需要以实际代码及所有日志/失败返回核验，不能直接把独立客户端 top-8 的草案套上去。

若两客户端数据不重叠，单次联合输出对于一条记录改变的上界可为 max(4,4)=4；三个独立公开 DP 工件 D01/D02/D03 同时发布时，同一记录可影响三次，基本组合上界 12。这里的数字都是**计划机制成立时的条件性上界**，不是已执行结果或当前代码的保证。实际 DP 发布数为 0；完整 FedFwd 参数/梯度通信 transcript、真实指导、无噪声工件不在该保证之内。

实现审查须确认安全、独立、不可从公开训练 seed 复现的噪声源；离散浮点采样对理想连续 Laplace 证明的偏差；空类、跨标签、并列、重复、发布顺序、异常/重试、日志、缓存和元数据。当前没有可审查的 ε4 实现，状态是 `reference_only`，不能标 verified。
