# Protocol handoff — audited portions and unresolved items

The historical seed-57 comparison uses DistilBERT adapter FedFwd, two logical clients (IDs 1 and 21), reported 120 local AG News training records per client, a fixed 512-example development set, and 50 updates plus a pre-training evaluation. All three recorded commands use α=0.5, learning rate 0.01, central finite-difference step 0.01, legacy ZO scaling, one cloud direction, batch size 8, and 64 cloud guidance slots balanced 16 per class. The source dataset and partition checksums are recorded in the original manifests but could not be rehashed from the inaccessible server. There is no official test outcome here.

The public pool contains 128 unique Qwen candidates (32 per class). A private record votes for one nearest public candidate within its class using a frozen embedding model. For each class, client 1 selects eight candidates by vote rank; client 21 then selects eight from the remaining candidates. Public-random uses a deterministic public hash ordering; public NLI scores the same pool and interleaves each class's top 16 into eight slots per client. The original generic generator had a private exact-duplicate rejection path; this pool has a recorded public-only replay yielding the same bytes, which does not validate other pools.

The proposed DP boundary is a fixed client roster and replace-one complete labeled record. If each record contributes one bounded vote to a fixed 128-coordinate histogram, its L1 sensitivity is at most two. An ideal one-shot, independent-coordinate Laplace scale-0.5 mechanism followed by the existing ordered, disjoint per-client top-8 post-processing would conditionally give ε=4, δ=0 for one release. This implementation is absent; empty classes, order, metadata, sampling, and zero-noise equivalence have not passed review. Three independently released trials would have a basic joint upper bound ε=12 for the same record. The FL gradient/update transcript remains unprotected by this proposed release mechanism.
