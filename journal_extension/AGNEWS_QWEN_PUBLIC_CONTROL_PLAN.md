# AG News Qwen public-selection control (locked before outcome)

Date: 2026-10-13. This is a **Non-DP** follow-up to the seed-57 GPU2 private-vote pilot. The immediate question is whether the private embedding vote adds utility beyond the same public Qwen candidate pool and a selection rule that never reads client records. No DP experiment is part of this run.

The prior pilot has a 128-record Qwen candidate pool (32 per class), SHA-256 `7e54c05ce2dc94d754b178218963dedfceb781c491b97ed1d9db5ab9e7d7c54f`, and 64 selected records. Before running FL, regenerate the entire pool with the same seed, prompts, decoding and filters **without loading private records or an exact-private-match set**. Require byte-identical SHA-256. This checks that the old pool was not changed by its private exact-match filter; abort the comparison if it differs.

Select 8 unique candidates per class for each of the same two client slots (1, 21) by a fixed SHA-256 ordering of public candidate indices, seeded with 57. The public selector reads only the verified pool; it must not read source-client files, votes or the private-vote selected texts. Retain 64 records, 16 per class, and the same 64-token maximum already enforced on the pool. Keep the selection manifest and candidate SHA. Audit requested-label agreement with the existing classifier only as a quality proxy; no classifier score enters selection.

Run one new `public_random_selection` arm with the exact downstream train command from the prior `private_vote_synthetic` arm, replacing only cloud H5 paths and output directory. Keep physical GPU2, fixed 512-record development partition, seed 57, 50 FL rounds, alpha 0.5, learning rate 0.01, and 51 evaluation points. Require at least 14,000 MiB free and at most 20% GPU2 utilization before Qwen replay and FL. Existing private-vote and same-source real runs are immutable references; compare them only after candidate-pool SHA, downstream command and data-partition hashes validate. Official test remains untouched.

Primary readouts: final development accuracy; last-ten-round mean; full accuracy/macro-F1/loss curve; public minus private-vote and public minus real differences. Report actual candidate overlap and class audit counts. One seed is a diagnostic, not evidence of statistical significance or client-scale generality. A random public selection is one necessary baseline but does not rule out a stronger public-only quality selector; if it is much worse than private vote, evaluate such a selector before attributing the full gap to private information. Only after this seed-57 control passes should the matched design be repeated over seeds 58/59. Do not infer privacy from any Non-DP output.

Raw candidate texts, cloud H5, and logs remain on server and in verified local backups. GitHub may receive code, this precommitted protocol, and aggregate metrics/curves only.
