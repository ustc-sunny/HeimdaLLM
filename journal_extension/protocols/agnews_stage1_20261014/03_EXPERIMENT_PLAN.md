# HeimdaLLM+：冻结协议后的扩刊实验方案

版本：2026-10-14。**这是待执行方案，不是实验结果。**
本方案取代此前“自动切换小生成器、聚类/概率采样、增加控制器”的探索任务；不撤销任何历史证据，也不覆盖历史产物。

## 1. 研究范围与本轮决定

保留 KDD 的两个技术内核：ZGR 算法、SPC/DTC 系统优化。新增一个完整贡献：在有限合成指导发布预算和端侧资源约束下，降低云端对现成真实同域指导数据的依赖，并研究发布隐私、实际指导质量与代价。

客户端的下游任务仍使用本地真实数据，DistilBERT adapter 与生成器 LoRA 是不同组件。本轮不把下游方法改成 LoRA，不重新开发通用生成器，不增加新系统控制器。

本轮仅推进已经建立的“公开候选池＋客户端有界投票＋一次性 DP 选择”实例。Qwen 只作为现有冻结候选池的来源，**不因此要求客户端部署 Qwen，也不预先认定它是最终最佳生成器**。路线 A（旧 DP-LoRA）保留为已记录的比较路线，不继续无假设地扫参数。

## 2. 执行范围与预算

### 2.1 本轮授权执行

1. 协议、数据和实际更新算子审计。
2. 固定池四臂 × FL seeds 57/58/59，共 **12 个 Non-DP/参考终点**。
3. 机制审计通过后，一个 ε=4 的 DP 私有选择臂 × 3 个配对试验，共 **3 个 DP 终点**。
4. 小规模离线梯度诊断、组件位置和成本记录、证据交接。

因此目标矩阵共 **15 个完整下游任务**，而不是立即跑所有投稿实验。若快照中的 3 个终点匹配且可复用，最多新增 12 个；若后来已有更多匹配完成任务则更少。协议审计发现旧结果不兼容时，最多重跑这 15 个目标任务，不扩展矩阵。技术故障最多额外重试 2 次，全局记录，不能根据精度重试。

以下不自动执行：全 ε 网格、Q 网格、新生成器、聚类、概率采样、刷新、自适应 α、新数据集、更多客户端、官方测试集。

### 2.2 不是所有工作都必须等实验完成

写作端可立即补研究问题、Insight 2、Challenge 3、条件性机制与理论、实验设计。完成结果只能通过证据清单导入，不能把计划写成实测结果。

## 3. E0：正确性和复用审计（先于训练）

### 3.1 仓库与协议

- 保存当前工作树状态、HEAD、未提交差异和环境清单；不覆盖用户改动，不 reset，不自动推送。
- 对比 KDD 最终实现、扩刊当前实现与各历史运行的真实命令/配置。
- 核对可训练参数名称与维度、损失 reduction、数值精度、有限差分步长、方向归一化、梯度恢复、学习率、聚合权重、同步顺序与指导频率。
- 特别记录估计器修正作用于哪些实验臂；禁止混用“修正前无指导”和“修正后有指导”。
- 跟踪云端梯度是否仅参与规定的指导路径；检查是否存在误把云端参数更新直接写入客户端/聚合器的路径。
- 用相同 checkpoint/batch/扰动做单步等价与小模型测试。有限差分应近似 BP 的**方向导数**，不是要求单方向 ZO 梯度等于 BP 全梯度。
- 若训练实际不使用正文假设的 V 子空间，写明真实算法，不改代码来迎合理论。

### 3.2 数据与有效预算

冻结：候选池内容/顺序及 hash、类别映射、tokenizer revision、源客户端、开发集、真实对照抽样、客户端与云端数据顺序。

分别记录：

- 64 个样本槽位；唯一文本数；同客户端/跨客户端重复；重复样本权重；是否云端去重；每轮 cloud BP 实际样本访问数。
- 私有投票每客户端每类 top-8；NLI 每类全局 top-16 后交错分配。保留这两个已定义选择器，不静默重写为相同算法。分别解释其多样性与分配方式。
- 各臂标签序列、初始化、调度、云端计算预算、ZOO queries 与评估时点的匹配。

若零噪声 DP 实现与现有 Non-DP 私有选择的文本/顺序不同，先找原因；不能把二者称为匹配噪声实验。

### 3.3 公开候选与 NLI 独立性

必须验证候选生成和公开选择不读取目标私有记录、票数、开发集标签或私有梯度。原 seed 57 的字节级重放审计只覆盖该池。

保留原始类内候选集合，不根据 NLI 分数预筛全部私有候选；否则改变了私有选择输入。固定 NLI checkpoint/revision、类别描述、评分方法与分配规则，不用新下游结果挑提示。

## 4. E1：固定候选池的四臂配对实验

### 4.1 固定设置

| 项目 | 本轮设置 |
|---|---|
| 数据 | 当前 AG News 原始文件及当前 partition，先读工件确认 |
| 源客户端 | 1、21，各 120 条（以真实索引审计为准） |
| 候选池 | 已冻结 Qwen2.5-3B-Instruct 公开池，4 类×32，共128候选 |
| 发布预算 | 每客户端每类8槽位，共64；唯一文本数另报 |
| 下游 | 当前审计后的 DistilBERT adapter＋FedFwd |
| 指导 α / LR | 快照为0.5 / 0.01；核对真实冻结协议，不静默调参 |
| 更新数 | 50 次；before_training 加 updates_completed=1…50 |
| FL seeds | 57、58、59 |
| 评估 | 原固定512条平衡开发集；官方测试集不使用 |
| 其他参数 | 按审计后的原协议冻结，不靠本文补猜默认值 |

四个 arms：

- `PUB_RANDOM`：既有公开确定性随机选择；选择种子固定，训练 seed 改变不重选数据。
- `PUB_NLI`：既有公开 NLI top-16/class＋交错客户端分配。
- `PRIVATE_ZERO`：既有无噪声客户端私有投票 top-8/client/class。
- `REAL_MATCHED`：既有同源真实指导，匹配槽位与标签；这是参考，不是理论上界。

固定池/固定指导集合下的三个 FL seeds 只覆盖训练随机性。本轮不将它们叫三个独立客户端群体。

### 4.2 指标与预先固定的终点

主要终点：updates_completed=50 的开发集 accuracy。辅助：macro-F1、loss、最后10次更新的均值、51点评估曲线、normalized accuracy AUC。

使用 trapezoidal AUC，x 为完成更新数0…50；除以50归一化，不把51点直接均值冒充积分。

预设 rounds/queries-to-target：50%、60%、70%；未达标标记 not_reached/right_censored，不填50伪装达标。额外探索阈值须标 exploratory。

核心配对差：

- PRIVATE_ZERO − PUB_NLI；PRIVATE_ZERO − PUB_RANDOM。
- PRIVATE_ZERO − REAL_MATCHED。
- 后续 PRIVATE_DP_E4 − PRIVATE_ZERO / PUB_NLI / REAL_MATCHED。

报告逐 seed、均值、样本标准差和明确方法的差值区间。3个重复的区间只作条件于固定池的探索性描述，不用“不显著”证明等效；轮次不是独立样本。

保存每类 precision/recall/F1、混淆矩阵、同一开发样本的配对正确/错误变化，重点检查 Science/Technology 与 Business 的互相误分。不用公开类别审计模型的同意率代替真实标签或隐私验证。

## 5. E2：记录级 DP 选择机制和 ε=4 小试

### 5.1 本轮明确的参考机制

定义固定客户端名册和公开候选池。邻接采用 **replace-one**：替换某客户端的一条完整记录，文本和标签均可改变；客户端是否参与、公开标签集合、每类输出配额固定。不是客户端级 DP，也不保护身份/流量匿名性。

每条记录用冻结公开编码器，在其标签对应的公开候选中选一个最近邻，严格贡献一张 one-hot 票。完整4类×32维向量记 h_i(D_i)。单条替换导致 L1 变化至多2。

一次性：

`h_tilde_i = h_i + Laplace(0, 2/epsilon)`（对完整向量各坐标独立采样）。

以 ε=4 得到尺度0.5。之后逐类从**同一个带噪向量**选 top-8。保留负带噪票数参加排序；不增加阈值、清零、补票、私有重排或新的数据访问。并列按固定公开 candidate ID 打破。

发布选中的公开候选 ID、固定槽位/标签和必要公开版本号；不发布原始票数、逐记录匹配、未保护排名。云端按公开池恢复文本，保留原有样本槽位权重。

若实际既有投票不是一条记录一票：停止本节 DP 训练，推导真实贡献界并明确改动，不静默把历史 PRIVATE_ZERO 更换为新选择器。

### 5.2 证明与实现审查

证明结构：完整直方图敏感度≤2 → 向量 Laplace 机制 → top-k/公开文本恢复为后处理。每类不是另花 ε=4，64个输出也不是64次查询。

两客户端记录不重叠、邻接只改变一个客户端的一条记录时，一次联合发布可用并行组合；同一客户端多次独立发布必须顺序组合。标准基础来自 Dwork–Roth；它不是本文新发明。

所有噪声在受信任的客户端执行区域产生，原始票数不传到假设不可信的云端。使用经审查的噪声采样路径，记录数学机制与实际有限精度/随机数实现的差别。单元测试是实现证据，不是 DP 数学证明。若数值安全或数据流条件未满足，不将该工件标为已验证的正式 DP 发布。

至少测试：同类替换、跨类替换、类别本地零记录、并列、重复记录、固定输出配额、禁止私有过滤、零噪声等价、发布白名单、无公开噪声 seed。数据集构造/预处理不得让一条记录变化影响其他记录的投票映射。

### 5.3 三个配对试验的随机性与预算

为 FL seeds57/58/59 各生成一个独立 DP 发布工件，标 release_trial=D01/D02/D03；每个客户端使用独立秘密随机性。**发布 ID/FL seed 不是可恢复 DP 噪声的 seed。** 不与公开随机臂共用 RNG，不将噪声 seed 写入 Git 或对云端可见日志。

这3个试验同时变化 DP 随机化与任务训练随机性，报告这一限制，不声称分别估计了两种方差。

记录每工件 ε=4、δ=0 的机制目标与审查状态。若三次独立发布都对同一观察者可见，针对同一客户端记录的联合预算最多按基本组合计为12，而不是4。Non-DP 对照、真实指导与完整未保护FL日志均不属于这条 DP 发布保证；AG News 分区作为研究基准，不据此宣称全部实验 transcript 是 DP。

保留 restricted raw artifacts，公开摘要中不要包含原始私有票数或可复原噪声材料。

### 5.4 通过与停止标准

机制正确性通过后才允许3个完整 DP 训练；不要求先在下游挑出“好”的噪声工件。所有预定 DP 工件都运行并报告，不 best-of-noise。

效用差也完成本轮报告，不自动放大 ε、换生成器、增加候选或重跑更好种子。不存在正向结果不是执行失败。

## 6. E3：最小机制诊断和成本记录

### 6.1 指导诊断

每个 seed 使用同一 `REAL_MATCHED` 轨迹的 checkpoint：更新前、完成10次、完成50次。每个 checkpoint 上用所有5种指导数据计算梯度与实际指导机制；不能用各臂自己的不同状态直接比较数据效应。

统一可训练参数、样本计权和有限差分尺度。保存 gradient cosine、相对梯度差、梯度norm；若真实算法有可提取V，则测参考真实梯度能量捕获和主角度。rank自适应时记录实际rank，零梯度给NA及原因。

辅助的2客户端rank≤2空间可以保留，但命名为diagnostic，不冒充生产历史指导空间。原始cosine保留方向符号；V的旋转/符号不唯一，不以相同z_g直接比较不同basis的GGD cosine作为主证据。

不增加端侧BP来选数据。诊断BP只在隔离的研究副本中执行，不影响正式训练；不把其成本藏入部署方案。
