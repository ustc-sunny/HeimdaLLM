# HeimdaLLM+ 扩刊思路与实验现状总结

**整理日期：2026-10-14**
**用途：** 供作者或其他分析者独立阅读，判断下一步研究路线。
**依据：** 本地已保存的实验报告、协议、结果汇总和最新代码；本文没有启动新训练，也没有把准备阶段当作已完成实验。服务器资源状态引用当天最近一次检查，不代表持续实时状态。

## 1. 当前判断

目前已有证据表明：在 AG News 的固定小规模协议下，合成数据可以替代云端真实指导数据，产生有效的下游指导；无噪声时，部分方案的精度接近同预算真实指导。

但扩刊所需的完整证据链尚未建立：**既要证明方法能提供有效指导，又要区分公开模型先验与额外私有信息的贡献，还要证明在明确的隐私约束下仍能保留有用精度。** 目前第一点已有较强的小规模证据，第二点在新路线中只有单种子支持，第三点仍未解决。

当前最值得分析的选择是：继续改进客户端 DP-LoRA 生成器，还是以“公开强生成器候选＋客户端选择”为主要研究路线。新路线的公开 NLI 选择对照已经准备好，但还没有下游训练结果，因此暂时不能判断私有投票是否优于更强的公开选择器。

## 2. 扩刊究竟改变什么

### 2.1 原 KDD 方法与扩刊的关系

原研究计划针对的部署假设是：云端有可用于计算指导方向的真实同域数据。扩刊希望用合成指导数据替代这一云端数据来源，并研究隐私与精度之间的权衡。

当前实验沿用 KDD 的 DistilBERT adapter＋FedFwd 下游训练路径。客户端继续使用本地真实训练数据进行任务模型训练；被替换的是**云端计算指导方向所使用的数据**，不是把整个联邦训练集替换成合成数据。

过去使用的 LoRA 是生成器适配方法：客户端用 LoRA 微调 DistilGPT2，再生成指导样本。它不是原 KDD 方法必须使用的组件，也不是本轮任务模型的 adapter。更换生成或选择方式，不要求把下游 KDD 方法改成 LoRA。

### 2.2 作者目前希望回答的问题

1. Non-DP 条件下，合成指导能否接近匹配的真实指导精度？
2. 合成指导的收益有多少来自公开模型和类别语义，有多少依赖客户端私有信息？
3. 对私有信息的使用加入严格隐私机制后，精度损失有多大？能否得到有意义的隐私—精度曲线？
4. 小规模结果能否在与 KDD 对齐的客户端规模、数据划分与训练预算下成立？

当前优先目标是精度和隐私。共享服务器上的运行时间只作为资源记录，不作为公平的速度性能结论。

## 3. 两条已探索的技术路线

| 路线 | 私有数据影响哪里 | 已验证到哪一步 | 主要未解问题 |
|---|---|---|---|
| A：客户端适配生成器 | 本地记录用于训练 DistilGPT2 LoRA，再生成指导文本 | Non-DP 长程有效；DP 生成与会计已跑通，但效用损失大 | 小客户端数据量下，带噪训练能否保留额外客户端信号？ |
| B：公开生成候选＋客户端选择 | Qwen 公开生成候选；本地记录通过嵌入相似度投票决定选哪些候选 | Non-DP 单 seed 有效；优于同池公开随机选择；强公开 NLI 对照准备完成 | 私有投票能否稳定胜过强公开选择？给选择过程加入 DP 后是否仍有收益？ |

路线 B 当前是一次性候选投票小试，受 Aug-PE 思路启发，不能称为完整迭代 Aug-PE。它没有微调生成器，也没有向生成 prompt 放入私有训练文本。但是**私有记录影响了发布哪些文本，现有无噪声选择仍没有 DP 保证**。

## 4. 已完成实验总览

以下 accuracy 均指各报告中的 AG News 固定开发集结果，通常为 512 条、四类平衡。50 轮实验的 final 指 round 49，即第 50 次更新后。`pp` 表示百分点。除明确标注单 seed 外，表中均值来自 seeds 57/58/59；不同实验的预算、训练实现和生成器不完全相同，不能跨行直接排名。

| 阶段 | 规模与状态 | 主要结果 | 可以支持的判断 |
|---|---|---|---|
| Non-DP v1 | 早期探索 | 基本未观察到明确合成指导收益；本总结不补造未核对的数值 | 原始生成配置不足，需要排查生成质量和训练条件 |
| Non-DP v2 | 3 seeds，5 轮 | 合成 37.43%；无指导 28.71%；同源真实 41.34%；异源真实 39.65%；乱标签合成 27.80% | 修正语义提示和生成长度后出现早期收益；合成−无指导平均 +8.72 pp |
| Non-DP v3 | 6 臂×3 seeds，50 轮，18/18 完成 | LoRA 合成 **76.17%**；同源真实 79.49%；异源真实 78.84%；公开 DistilGPT2 39.06%；无指导 28.71%；乱标签 27.47% | 收益持续到 50 轮；LoRA 合成平均距同预算同源真实 −3.32 pp |
| DP-LoRA v1 | 4 个 ε×3 seeds，50 轮，12/12 完成 | ε=8/4/2/1：**39.84/39.71/43.10/40.23%** | 生成发布的 DP 会计达到设定目标，但效用接近旧公开生成器，未得到清晰的效用保持曲线 |
| 匹配 Non-DP 消融 | 6 臂×3 seeds，50 轮，18/18 完成 | ordinary 71.68%；fixed-example 74.74%；Poisson 70.51%；clipped/no-noise 72.66%；public 41.67%；校准无指导 33.07% | FP32、逐样本目标、Poisson 或裁剪单独不足以解释约 40% 的 DP 结果 |
| 同管线噪声桥 | 2 臂×3 seeds，50 轮，6/6 完成 | zero-noise **72.92%**；DP ε≤8 **37.57%** | 在这条匹配管线中，加噪伴随约 **35.35 pp** 的下降，是定位效用问题的主要证据 |
| 旧 DP 输出公开筛选 | 3 臂×3 seeds，50 轮，9/9 完成 | filtered DP **54.62%**；random DP 32.62%；filtered public **55.47%** | 筛选提高了效用，但 filtered DP 未优于匹配的 filtered public |
| Qwen＋私有投票小试 | seed 57，2 臂，50 轮，2/2 完成 | 私有投票合成 **75.00%**；同源真实 **72.07%**，各 64 条指导 | 不适配生成器也能得到有效指导；单 seed 不能说明普遍优于真实指导 |
| 同 Qwen 候选池公开随机选择 | seed 57，新完成 1 臂，50 轮 | 公开选择 **70.31%**，对照已完成的私有投票 75.00% | 私有投票相对这一公开随机选择为 **+4.69 pp**；尚需更强公开选择和重复实验 |
| 同候选池公开 NLI 选择 | 64 条选择与 CPU 审计已完成 | 类别同意率 **59/64＝92.19%**；**下游 accuracy 未知** | 仅说明候选选择与质量审计已完成，不能推断训练精度 |

### 4.1 v3 的逐 seed 结果与诊断

v3 每个指导臂使用 128 条指导样本；源客户端为 1、21，每轮两个逻辑客户端参与。全部 18 条轨迹每条有 51 个评估点，共 918 个；结果不是只比较某个最好轮次。

| Seed | LoRA 合成 | 公开 DistilGPT2 合成 | 同源真实 | LoRA 合成−同源真实 |
|---:|---:|---:|---:|---:|
| 57 | 81.05% | 42.58% | 81.25% | −0.20 pp |
| 58 | 75.98% | 36.52% | 77.54% | −1.56 pp |
| 59 | 71.48% | 38.09% | 79.69% | −8.20 pp |
| 均值 | 76.17% | 39.06% | 79.49% | −3.32 pp |

合成指导最后十轮均值为 76.09%，其优势在观察窗口内没有消失。不过 seed 59 仍明显落后于真实指导；“均值接近”不等于已证明统计等效。

初始 checkpoint 的机制诊断也支持 LoRA 合成含有更有用的客户端信息：它与 source-real 梯度的平均 cosine 为 0.8148，公开合成为 0.6678；两客户端合成梯度子空间捕获的 source-real 梯度能量为 0.6681，公开合成为 0.4539。这只是单个初始 checkpoint、rank≤2 子空间的辅助证据，不能替代多轮训练或更多客户端的验证。

### 4.2 旧 DP 路线的问题定位

DP-LoRA v1 使用 δ=10⁻⁵；四个目标 ε 对应实际会计上界约为 7.9993、3.9935、1.9918、0.9930，均不超过目标。各条件 accuracy 的 sample SD 约为 6–7 pp，所以 ε=2 的均值较高不能解释为“更强隐私提高精度”。有限次随机实验的精度也不必严格随 ε 单调变化。

直接用 v3 对比 DP v1 会混入裁剪、采样、浮点精度等变化。后续匹配消融和同管线噪声桥减少了这些混杂，因此“当前 DP 生成训练中的噪声带来了较大效用代价”比早期猜测更有依据；它仍不等于“所有 DP 合成方法都不可行”。

公开筛选将旧 DP 输出改善到 54.62%，但公开模型输出经过同样筛选已有 55.47%。这说明更好的标签一致性可以改善指导质量，尚不能说明旧 DP 输出保留了超出公开先验的有效私有信息。

## 5. 当前重点：Qwen 公开候选＋私有投票

### 5.1 固定协议

| 项目 | 设置 |
|---|---|
| 公开生成器 | Qwen2.5-3B-Instruct，不做本地适配 |
| 候选预算 | 每类 32 条，共 128 条；使用公开类别语义提示 |
| 私有投票 | 客户端 1、21，各 120 条本地记录；公开 MiniLM 嵌入；类别内近邻投票 |
| 发布预算 | 每客户端每类 8 条，共 64 条，类别平衡 |
| 下游 | DistilBERT adapter＋FedFwd；α=0.5；学习率 0.01；50 轮；seed 57 |
| 评估 | 固定 512 条开发集，训练前及每轮评估；未使用官方测试集 |
| 隐私 | 当前投票无噪声，无 DP 会计；下游 FL 同样为 Non-DP |

旧候选生成程序曾有“与私有文本精确匹配则拒绝”的过滤条件。10 月 13 日通过完全不读取私有记录的路径重放候选，得到与原候选字节级相同的 SHA-256。因此当前对照中的候选池经验证未被该私有过滤改变，可以用于同池公开选择对照。该审计不能自动推广到将来的其他 seed 或候选池。

### 5.2 已有严格配对对照

| 指导方式 | Final accuracy | 最后十轮平均 accuracy | 类别同意率代理 |
|---|---:|---:|---:|
| 私有记录投票 | **75.00%** | **74.80%** | 89.06% |
| 公开确定性随机选择 | 70.31% | 70.16% | 89.06% |
| 同源真实指导 | 72.07% | 71.58% | 不适用 |
| 公开 NLI 选择 | **尚未训练** | **尚未训练** | **92.19%** |

私有投票与公开随机选择的 final 差为 +4.69 pp、最后十轮差为 +4.65 pp。两者选中文本重合 31/64，类别同意率相同。总体净正确数差为 24/512；其中 Science/Technology 类私有投票正确 74/128，公开选择正确 49/128。这值得做类别覆盖与指导方向诊断，但不能凭一次实验确定原因。

同源真实指导是直接使用对应客户端真实记录的精度参照（oracle），不是隐私可部署方案，也不是已经完成的 KDD 全规模主实验。

已有证据说明公开 Qwen 先验本身很有用；私有投票在这一次配对比较中又带来增益。**问题已从“能否生成有效文本”推进到“私有选择的增益是否稳定且值得为其消耗隐私预算”。**

### 5.3 新的公开 NLI 对照：已做与未做

已完成：用冻结的 `facebook/bart-large-mnli` 按目标类别分数排序，从同一候选池每类选最高的 16 条，交错分给两个客户端槽位。选择代码只读取公开候选，不读取本地私有记录、旧投票结果或开发集标签。独立 AG News 分类器对 64 条中的 59 条与目标标签一致；剩余 5 条均为 Business 被判为 Science/Technology。样本长度均不超过 64 tokens。

未完成：这 64 条 NLI 选择数据的 50 轮 FedFwd 训练。**92.19% 是辅助分类器同意率，不是下游任务 accuracy。** 因而不能写成 NLI 已超过 75% 的私有投票。

训练驱动、GPU 映射参数和数据校验已经准备好。当天最近一次检查中，GPU1 可用显存为 9250 MiB（约 9.03 GiB），未达到已有预检的 14000 MiB（约 13.67 GiB，此前口头约称 14 GiB）。较低门槛的启动尝试被自动审批拒绝，之后已恢复原门槛，训练没有启动。这个门槛是共享 GPU 的预检条件，不能解释为已测得的模型峰值显存需求。

## 6. 论文目前可以写什么，不能写什么

| 拟议表述 | 当前证据是否足够 |
|---|---|
| 在固定 AG News 小规模设置中，Non-DP 合成指导可有效支持 FedFwd | 有支持，来自 v3 多 seed 和 Qwen 单 seed 结果 |
| 在 50 轮观察窗口内，LoRA 合成指导的优势持续存在 | 有支持；不等于无限长训练后的收敛定理 |
| 在相同预算下，部分 Non-DP 合成方案精度接近真实指导 | 可作限定的描述性表述；尚未证明等效或非劣 |
| 私有 Qwen 投票普遍优于强公开选择 | 不足；只有一个候选池、一个 FL seed 和一个公开随机选择对照 |
| 不使用 LoRA 也能得到有效合成指导 | 小规模 Non-DP 有支持；不能据此证明隐私安全 |
| 已达到原 KDD 全规模精度 | 不足；目前两客户端小试不能替代 KDD 规模对齐实验 |
| 已得到效用保持良好的正式隐私—精度曲线 | 不足；旧 DP 路线已测但损失大，新投票路线尚无 DP 结果 |
| 整个联邦训练满足端到端 DP | 不支持；现有下游更新通道未受 DP 保护 |

还应正视无指导基线：v3 的无指导均值为 28.71%，几乎不学习；后续经独立校准的版本为 33.07%，且使用了明确标注的估计器修正与额外调参查询。它不能作为充分优化的无云指导上界，也不能与旧版无指导混称同一设置。论文的主要证据应落在匹配真实指导和匹配公开选择对照上。

类别审计模型训练于 AG News；它只是质量代理，不是独立标签真值。多轮反复使用固定开发集也会产生研究决策对该开发集的适应，应在方案冻结后再使用官方测试集。轮次不能当作相互独立的统计重复；多个 FL seeds 也不能替代不同候选池和不同客户端划分。

## 7. 待作者判断的下一步方案

以下是供讨论的建议，**不是已经启动的实验或已获支持的论文结论**。

### 7.1 优先完成现有 NLI 对照

这一臂已经完成数据准备，复用冻结的 seed-57 协议即可回答一个直接问题：私有投票相对公开随机选择的 +4.69 pp，是否会被更好的公开选择消除？比较 final、最后十轮平均、macro-F1 和完整轨迹，并核对数据预算、标签分布、下游顺序与初始化。

| 观察到的结果 | 对研究路线的含义 | 建议后续 |
|---|---|---|
| 私有投票仍高于 NLI 选择 | 获得相对更强公开对照的单次支持 | 配对重复 seeds 58/59，再换候选池和客户端划分 |
| NLI 与私有投票相近或更好 | 当前私有访问的必要性受到削弱 | 检查更有分布差异的客户端场景；避免继续把全部合成收益归于私有信息 |
| 各方案随重复大幅波动 | 单 seed 差距不足以指导方法选择 | 优先增加重复、核查基线稳定性与数据质量，而非马上扫 ε |

不要事后根据一个最好 seed 决定“接近”的含义。若论文要声称接近真实指导，应事先约定可接受精度差距，并报告配对差值、逐 seed 数据和不确定性，而不只看均值。

### 7.2 将重复实验拆成两层

第一层固定当前候选池和指导数据集合，仅增加 FL seeds，比较私有投票、公开随机、公开 NLI、同源真实四臂，隔离下游训练随机性。这一层即使有三个 seeds，仍只代表一个候选池。

第二层改变候选生成 seed、公开随机选择 seed、源客户端和数据划分；对每个新候选池重新做公开/私有选择，并进行配对下游训练。这才逐步回答方法能否泛化到不同生成样本与客户端分布。

### 7.3 若决定研究 DP 选择，先冻结隐私定义

必须明确保护单条记录还是整个客户端，采用何种邻接关系，谁看到原始投票，发布哪些对象，以及重复发布和多客户端如何组合。标签、每类数量、选择索引和任何依赖私有数据的过滤也要进入边界。

公开候选生成与公开质量筛选不访问目标私有记录；私有投票选择访问私有记录，不能因为输出文本来自公开候选就自动获得 DP。旧 DP-LoRA 的会计也不能直接套用到新投票机制。

建议先建立与 Non-DP 完全匹配的选择管线，完成贡献上界、加噪机制、会计及实现审查，再做少量验证。多次无噪声选择不具备 DP；加噪也不自动保证实现满足预期 DP。只有机制和效用都通过初步检查，才值得扩展 ε 网格。

正式曲线应在固定 δ 和匹配预算下报告 ε 与精度；噪声系数 σ 可以同时列出，但不能替代会计结果。Non-DP 对照需单独标识，不能写成 ε=0。

即使选择发布满足 DP，当前下游 FL 更新仍是另一个信息通道。论文应明确“合成指导发布的隐私保护”这一范围，除非后续另行保护并核算完整训练 transcript。

### 7.4 方法确定后补全论文规模证据

- 对齐 KDD 的任务模型、客户端总数与每轮参与数、数据划分、每客户端数据量、训练预算、指导预算和超参数。准确数量应以 KDD 最终论文与实际启动脚本逐项核对，不能直接套用早期扩刊计划。
- 可保留两客户端实验作为机制诊断，但若声称保持 KDD 精度，应增加与 KDD 设置匹配的主实验。逻辑客户端数不由物理 GPU 数决定；复用一张 GPU 时需保持算法调度语义一致。
- 至少增加另一数据集或更有代表性的异质划分，报告失败和退化场景。先明确需要支撑哪条结论，再决定额外数据集和模型数量。
- 固定方案后评估官方测试集，报告真实指导、公开指导、Non-DP 私有指导和 DP 私有指导的配对结果。
- 若扩刊还保留通信或系统贡献，需要补充相应证据；当前共享 GPU 的小规模 accuracy 实验不能支撑速度或完整系统优势。

7. 在进入大规模论文实验前，是否应先解决无指导基线偏弱的问题，以及固定开发集反复用于研究决策的局限？
